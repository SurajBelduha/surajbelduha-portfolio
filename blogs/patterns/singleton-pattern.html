Understanding Singleton Design Pattern in .NET

A practical guide to the Singleton Design Pattern in .NET, including thread-safe implementations with lock and Lazy<T>, plus when to use container-managed AddSingleton in ASP.NET Core.

July 11, 2026 • .NET • 11 min read
#design-patterns #singleton #dotnet #dependency-injection

1. What Is the Singleton Design Pattern?

The Singleton Design Pattern is a creational pattern that restricts the instantiation of a class to one single object throughout the entire lifetime of an application. It ensures that every part of the codebase shares that exact same instance.

2. The Problem Without Singleton

Without Singleton, creating expensive objects repeatedly (like database connection pools, memory caches, or hardware loggers) wastes memory and causes state synchronization bugs across multiple threads.

3. Implementing the Singleton Pattern

A standard C# Singleton class relies on three key rules:

  • A private constructor to prevent external new instantiation.
  • A private static field holding the single instance.
  • A public static property providing global access.

4. The Thread Safety Problem

In multi-threaded environments (such as ASP.NET Core Web APIs handling concurrent HTTP requests), two threads executing simultaneously might both check if the instance is null at the exact same millisecond, instantiating two separate objects!

5. Creating a Thread-Safe Singleton

public sealed class LockBasedSingleton
{
    private static LockBasedSingleton? _instance;
    private static readonly object _padlock = new object();

    private LockBasedSingleton() {}

    public static LockBasedSingleton Instance
    {
        get
        {
            lock (_padlock)
            {
                _instance ??= new LockBasedSingleton();
                return _instance;
            }
        }
    }
}

6. Singleton Using Lazy<T>

.NET provides the built-in Lazy<T> type which handles thread safety and lazy evaluation natively under the hood:

public sealed class GlobalCurrencyCache
{
    private static readonly Lazy<GlobalCurrencyCache> _instance = 
        new Lazy<GlobalCurrencyCache>(() => new GlobalCurrencyCache());

    public static GlobalCurrencyCache Instance => _instance.Value;

    private GlobalCurrencyCache()
    {
        // Private constructor prevents external instantiation
    }
}

7. Singleton in Modern .NET Applications

In ASP.NET Core, you rarely write manual Singleton classes. Instead, you register services with the built-in Dependency Injection container:

builder.Services.AddSingleton<IMemoryCache, MemoryCache>();

8. Manual Singleton or AddSingleton? (Captive Dependencies)

When using AddSingleton in ASP.NET Core, beware of Captive Dependencies. Injecting a Scoped service (like DbContext) into a Singleton holds that DbContext alive forever, causing memory leaks.

// ✅ GOOD SOLUTION: Inject IServiceScopeFactory in Singleton
public class MetricCollectorService
{
    private readonly IServiceScopeFactory _scopeFactory;
    public MetricCollectorService(IServiceScopeFactory scopeFactory) => _scopeFactory = scopeFactory;

    public async Task SaveMetricAsync(MetricLog log)
    {
        using var scope = _scopeFactory.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<ApplicationDbContext>();
        db.Metrics.Add(log);
        await db.SaveChangesAsync();
    }
}

9. Conclusion

The Singleton pattern remains a cornerstone of .NET software engineering. By understanding Lazy<T> and container-managed AddSingleton, you can build low-latency, memory-efficient enterprise APIs.
