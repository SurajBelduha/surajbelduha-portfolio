Stop Injecting IEnumerable Just to Pick One Service in C#

Suraj Prajapati Senior .NET Backend Developer • FinTech Specialist

A common architectural anti-pattern in C# applications when supporting multiple strategy implementations (e.g. payment channels like UPI, Card, Payout) is injecting IEnumerable<IPaymentGateway> into a processing service and using LINQ to filter out the matching strategy at runtime.

📌 What You Will Master (15 Min Guide):

  1. Why IEnumerable<T> injection hurts performance and creates GC allocation spikes.
  2. How the DI container resolves every single strategy on every request.
  3. Refactoring Option 1: Native **.NET 8 Keyed Services** (`AddKeyedScoped` + `[FromKeyedServices]`).
  4. Refactoring Option 2: Factory Resolver Delegates.

1. The Problem with IEnumerable Injection

// ❌ BAD: Instantiates ALL registered services on every request!
public class PaymentService
{
    private readonly IEnumerable<IPaymentGateway> _gateways;

    public PaymentService(IEnumerable<IPaymentGateway> gateways)
    {
        _gateways = gateways; // DI Container resolves ALL implementations!
    }

    public async Task ProcessPaymentAsync(string gatewayName, PaymentRequest req)
    {
        var gateway = _gateways.FirstOrDefault(g => g.Name == gatewayName);
        if (gateway == null) throw new NotSupportedException();
        await gateway.ExecuteAsync(req);
    }
}

Why is this bad? It forces the DI container to instantiate every single registered payment gateway class on every HTTP request, creating unnecessary objects, connecting to unused databases, and triggering Garbage Collector pressure.

2. Solution 1: Native .NET 8 Keyed Services

Starting with .NET 8, C# natively supports Keyed Services via AddKeyedScoped and [FromKeyedServices]:

// 1. Program.cs Registration
builder.Services.AddKeyedScoped<IPaymentGateway, UpiGateway>("UPI");
builder.Services.AddKeyedScoped<IPaymentGateway, CardGateway>("Card");
builder.Services.AddKeyedScoped<IPaymentGateway, PayoutGateway>("Payout");

// 2. Direct Resolution in API Controller / Handler
public class PaymentController : ControllerBase
{
    public async Task<IActionResult> Process(
        [FromKeyedServices("UPI")] IPaymentGateway gateway, 
        PaymentRequest req)
    {
        await gateway.ExecuteAsync(req);
        return Ok();
    }
}

3. Solution 2: Factory Resolver Delegate

// Program.cs
public delegate IPaymentGateway GatewayResolver(string name);

builder.Services.AddScoped<GatewayResolver>(sp => name => name switch
{
    "UPI" => sp.GetRequiredService<UpiGateway>(),
    "Card" => sp.GetRequiredService<CardGateway>(),
    _ => throw new NotSupportedException($"Gateway '{name}' is not registered.")
});
