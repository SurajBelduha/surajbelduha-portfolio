Understanding Singleton, Scoped, and Transient Lifetimes in .NET 8: A 15-Minute Guide

Suraj Prajapati Senior .NET Backend Developer • FinTech Specialist

Dependency Injection (DI) is a core design pattern in ASP.NET Core used to achieve Inversion of Control (IoC). When registering a service in the DI container, specifying the correct service lifetime dictates when an object is instantiated, how long it lives in memory, and when it gets disposed of by the runtime.

📌 What You Will Master (15 Min Guide):

  1. Difference between Transient, Scoped, and Singleton lifetimes.
  2. Real-life analogies to easily remember each lifetime.
  3. C# Code Example demonstrating GUID lifetime tracking across HTTP requests.
  4. Avoiding memory leak traps and Captive Dependencies.

1. Transient Lifetime (AddTransient)

Analogy: Disposable paper coffee cups — every time a customer orders coffee, a brand-new paper cup is created, used once, and thrown away immediately.

A new instance is created every single time the service is requested from the DI container, even within the same HTTP request.

// Good for lightweight, stateless processing services
builder.Services.AddTransient<IEmailValidator, EmailValidator>();

2. Scoped Lifetime (AddScoped)

Analogy: A customer tray at a restaurant — shared throughout your single dining visit, but discarded when you finish your meal and leave.

A single instance is created once per HTTP request scope. All components invoked during that HTTP request share the exact same instance.

// Essential for DbContext, Unit of Work, and User Context per HTTP request
builder.Services.AddScoped<IApplicationDbContext, ApplicationDbContext>();
builder.Services.AddScoped<IPaymentRepository, PaymentRepository>();

3. Singleton Lifetime (AddSingleton)

Analogy: The main espresso machine in the coffee shop — created once when the shop opens and used by all employees for every customer all day long.

A single instance is created once when the application starts and reused across the entire application lifecycle for all users and requests.

// Good for thread-safe memory caches, configuration objects, and metrics
builder.Services.AddSingleton<IMemoryCache, MemoryCache>();

Summary Comparison Matrix

Lifetime Creation Frequency Disposal Boundary Typical Production Use Case
Transient Every time requested When resolving container/scope ends Stateless helpers, lightweight validators
Scoped Once per HTTP Request End of HTTP Request DbContext, Repositories, Request User Context
Singleton Once per App Lifetime Application Shutdown Memory Cache, Feature Flags, Metrics Logger
